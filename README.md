# 2026 年电赛多任务运动控制系统

基于 STM32F407ZGT6 的嵌入式运动控制项目，面向电赛小车、二维倾斜平台和钢球平衡场景，集成灰度循迹、编码器反馈、PID 控制、摄像头数据解析、OLED 显示和多任务状态机。

项目采用主循环处理非实时事务、TIM6 以 10 ms 周期执行实时控制的结构。主循环负责通信数据解析、OLED 刷新和按键任务确认；定时器中断负责编码器采样、速度控制、灰度循迹、钢球平衡和电机输出更新。

## 项目功能

### 多任务控制

通过按键选择任务，短按切换任务编号，长按确认后锁存任务并启动对应控制流程。

- 任务 2：灰度循迹。读取灰度传感器位图，计算线路位置误差，并使用 PID 调整左右轮速度差。支持启动 S 曲线、定时降速、连续三路黑线终点识别和短时反向制动。
- 任务 3：钢球分段目标控制。通过 USART3 接收摄像头发送的钢球位置与速度数据，先追踪 +50 mm 目标，进入目标区域后切换到 -50 mm 目标，并使用位置误差和速度反馈进行 PID 控制。
- 任务 4：定时 S 曲线运动与钢球零点保持。底盘按照固定时长的 S 型加减速曲线运行，运动过程中并行保持钢球在平台零点附近，并使用独立的钢球 PID 与加速度前馈参数。
- 任务 5：稳定灰度循迹与钢球零点保持。采用平滑启动和终点 S 型减速，降低急停对钢球平衡的扰动，车辆停止后继续保持钢球零点。
- 任务 6：启动目标保持与稳定循迹。任务确认后采集连续有效摄像头帧，计算启动位置平均值作为钢球目标，运行和停车期间持续保持该目标位置。

## 控制与数据链路

灰度传感器 → 灰度位置 PID → 四轮速度目标 → 编码器速度 PID → 底盘电机

摄像头 → USART3 DMA → 固定帧解析 → 钢球位置与速度 → 钢球平衡 PID → 平台倾角目标 → 转向电机位置闭环

### 钢球摄像头协议

摄像头使用固定 13 字节 ASCII 数据帧：ly±ddd±sssscs。

- ly：帧头。
- ±ddd：钢球位置，单位为毫米。
- ±ssss：钢球速度，单位为毫米每秒。
- cs：帧尾。

解析器支持半帧、单帧和连续多帧输入，并检查帧头、符号、数字字段、帧尾和位置范围。通信超时或数据失效时，控制器会清除 PID 历史，并让平台目标平滑回到水平基准，避免继续使用过期视觉数据。

### 编码器反馈

工程包含 TIM1 转向编码器和 TIM2、TIM3、TIM4 底盘编码器接口。转向编码器使用正交计数模式，并提供可在 Keil Watch 中观察的调试状态，包括原始计数、10 ms 周期增量、处理回绕后的累计计数、采样次数和启动状态。

当前参数按电机轴每圈 500 线、正交四倍频和 30:1 标称减速比计算，理论上对应减速箱输出轴每圈 60000 个计数。实际使用前应通过输出轴整圈试验校准线数、减速比、方向和机械回差。

## 硬件与外设

- 主控：STM32F407ZGT6。
- 开发环境：STM32CubeMX、STM32 HAL 和 Keil MDK-ARM。
- 底盘：四轮电机、PWM 驱动和四路编码器反馈。
- 平台：倾角执行电机、转向位置编码器和位置闭环。
- 传感器：七路灰度传感器默认参与循迹，可配置为八路模式。
- 视觉接口：USART3 加 DMA 接收钢球摄像头数据。
- 显示与交互：软件 I2C OLED、按键任务选择与确认。
- 控制周期：TIM6 提供 10 ms 实时控制节拍。
- 姿态接口：工程包含 HWT101 相关驱动，当前主要用于偏航角数据读取。

## 软件结构

- Core：主函数、外设初始化、中断入口和 CubeMX 生成的基础代码。
- Hardware：应用层、PID、底盘运动、编码器、灰度、钢球平衡、OLED、按键等业务模块。
- Drivers：STM32 HAL、CMSIS 和相关底层驱动。
- MDK-ARM：Keil 工程文件和构建配置。
- Hardware/Tools：OLED 字库生成工具和 HEX 文件合并工具。
- diansai.ioc：STM32CubeMX 工程配置。
- 钢球平衡控制方案.md：钢球平衡控制设计与调试方案。

主要业务模块包括 My_app、My_gray、My_ball_balance、My_encoder、My_pid、My_move、My_steering、My_oled 和 My_key，分别负责任务状态机、灰度循迹、钢球平衡、编码器处理、PID 运算、底盘运动、平台转向、显示和按键输入。

## 编译与下载

1. 使用 Keil MDK-ARM 打开 MDK-ARM/diansai.uvprojx。
2. 确认芯片型号、编译器、CMSIS 组件和下载器配置正确。
3. 选择 main 目标并执行 Build 或 Rebuild。
4. 下载前确认电机、平台和急停措施处于安全状态。
5. 上电后先观察 OLED、编码器和通信状态，再逐步确认具体任务。

如果需要重新生成 CubeMX 代码，应先保存 diansai.ioc，并确认业务代码仍位于用户代码区或 Hardware 自建模块中。外设引脚、时钟、DMA 和中断配置应通过 CubeMX 统一修改，不建议直接改写生成区。

## 调试建议

1. 单独确认电机方向、PWM 输出和急停逻辑。
2. 验证四路底盘编码器速度反馈和转向编码器方向。
3. 低速验证灰度传感器位图、线路方向和停车线识别。
4. 验证摄像头协议帧、位置单位、速度方向和通信超时保护。
5. 在平台静止时调试钢球位置与速度反馈，再加入底盘运动。
6. 逐步提高速度和加速度，检查 S 曲线、加速度前馈和终点停车效果。

钢球平衡效果会受到摄像头标定、视觉噪声、通信延迟、平台机械回差、电机死区和车体振动影响。正式验收前应分别记录静止和运动工况下的位置误差、峰值误差、均方根误差、进入目标区域所需时间、丢帧率和端到端延迟。
